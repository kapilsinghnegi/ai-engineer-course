# Embeddings Without Math

## Why keyword-based retrieval is limited

In the previous lesson, our basic retrieval function searched for exact keywords. This approach works for simple cases but struggles when a user expresses the same idea using different words.

Imagine the knowledge base contains:

> “There is a jam on Main Road.”

A user asks:

> “How much traffic is there on Main Road right now?”

A human can connect the two sentences because a traffic jam indicates heavy traffic. However, a basic keyword-matching function may fail if it only looks for the exact phrase `"traffic jam"` or a particular keyword.

Other examples:

| Knowledge base                 | User query                              |
| ------------------------------ | --------------------------------------- |
| “The application is slow.”     | “Why is the app taking so long?”        |
| “The employee has paid leave.” | “How many vacation days are available?” |
| “A cat is an animal.”          | “Which animals are cats?”               |

The wording differs, but the meaning may overlap.

### Problems with keyword-based retrieval

- Spelling mistakes: The user misspells a keyword.
- Different wording: The user asks the same question using different words.
- Synonyms: Words such as “vacation” and “leave” may refer to related concepts.
- Context: A keyword by itself may not capture what the user actually means.

The central idea: We want retrieval to recognize semantic similarity, not merely exact word matches.

## What are embeddings?

An embedding is a numerical vector representation of data, such as text, that is produced by an embedding model.

Instead of storing a sentence only as text, we can convert it into a list of numbers. A computer can then compare these numerical representations to estimate how semantically related two pieces of text are.

Suppose we represent food using two manually selected features:

- Sweetness
- Crunchiness

We could create this illustrative table:

| Food item | Sweetness | Crunchiness | Example vector |
| --------- | --------- | ----------- | -------------- |
| Apple     | 8         | 7           | `[8, 7]`       |
| Cake      | 10        | 2           | `[10, 2]`      |
| Cracker   | 1         | 9           | `[1, 9]`       |
| Milkshake | 10        | 0           | `[10, 0]`      |

### What the example teaches

Apple and cake

Their sweetness scores are close, and their vectors are relatively similar under this simple representation.

Cake and Cracker

Their scores differ substantially, so the vectors are farther apart under this representation.

The lesson is that numerical representations let us compare data using mathematical operations.

In real NLP systems, however, we generally do not manually assign features such as sweetness or crunchiness. A trained embedding model learns useful numerical representations from data.

### Definition to remember

> An embedding is a vector of numbers generated by a model to represent information in a form that makes meaningful relationships computationally comparable.

Embeddings can be generated for text, images, audio, and other data types, depending on the model.

## Vectors and dimensions

A vector is an ordered collection of numerical values.

For example:

```py
apple_vector = [8, 7]
cake_vector = [10, 2]
```

Each vector has two dimensions because each contains two numbers.

- Dimension 1 represents sweetness.
- Dimension 2 represents crunchiness.

This is a deliberately simple example. Actual embedding dimensions represent learned patterns and are not usually individually interpretable as specific human-defined features.

### What does embedding dimension mean?

The embedding dimension is the number of numerical values in a vector.

For example:

```py
vector = [0.12, -0.08, 0.34, 0.51]
```

This vector has four dimensions.

The lesson demonstrates the `all-MiniLM-L6-v2` sentence-transformer model, which produces 384-dimensional embeddings.

That means a sentence is represented by a vector containing 384 numerical values.

```py
# Conceptual example
sentence = "Machine learning is fun"
embedding = [ 0.12, -0.08, 0.34, ... ] 
# Actual vector length for all-MiniLM-L6-v2: 384
```

The exact numbers are generated by the model. You generally don't choose each dimension yourself or assign a manual meaning to it.

### Does a higher dimension always mean a better embedding?

No. A larger vector does not automatically guarantee better results. Embedding quality depends on the model's training, the task, the data, and how retrieval is evaluated. Larger vectors can also require more storage and computation.

## How similarity between embeddings works

Once two pieces of text have been converted into vectors, we can compare those vectors to estimate how similar the underlying information is.

Consider these sentences:

- Sentence A: “There is a traffic jam.”
- Sentence B: “Traffic is very heavy.”

Their exact words differ, but their meanings are closely related. A good embedding model may represent them as similar vectors.

Now compare:

- Sentence A: “There is a traffic jam.”
- Sentence C: “I love pizza.”

These sentences have little semantic relationship, so their embeddings would generally be less similar.

### The basic workflow

1. Sentence A: “There is a traffic jam.” -> Embedding model -> Vector A: [0.12, -0.08, 0.34, ...]
2. Sentence B: “Traffic is very heavy.” -> Embedding model -> Vector B: [0.15, -0.06, 0.31, ...]
3. Compare vectors
4. Calculate a similarity score

The vector values above are illustrative, not actual model output.

A similarity measure helps us rank candidate documents. The system can then retrieve the most relevant results rather than requiring exact keyword overlap.

## Cosine similarity

The lesson introduces cosine similarity as a way to compare two vectors.

Conceptually, cosine similarity measures how closely two vectors point in the same direction.

- Vectors pointing in similar directions tend to have high cosine similarity.
- Vectors at approximately a right angle have cosine similarity near zero.
- Vectors pointing in opposite directions have negative cosine similarity.

For nonzero vectors, the mathematical formula is:

```
cosine similarity (A, B) = A.B / ||A||||B||
```

Here:

- `A.B` is the dot product of the vectors.
- `||A||` is the magnitude, or length, of vector `A`.
- `||B||` is the magnitude, or length, of vector `B`.

You don't need to memorize the formula immediately to understand the practical concept: compare vector directions to estimate similarity.

### Interpreting the score

| Cosine similarity | General interpretation               |
| ----------------- | ------------------------------------ |
| Close to `1`      | Vectors point in similar directions  |
| Close to `0`      | Vectors are approximately orthogonal |
| Close to `-1`     | Vectors point in opposite directions |

These are mathematical interpretations, not universal thresholds for deciding whether two sentences mean the same thing. Actual scores depend on the embedding model and dataset.

Important distinction: Cosine similarity is not the same as cosine distance. A common definition of cosine distance is:

```
dcosine = 1 - cosine similarity
```
Higher similarity generally means a stronger match; lower distance generally means a closer match.

## Generating embeddings with Python

### Step 1: Install the libraries

Using `uv`:

```
uv add numpy sentence-transformers
```

Or with pip:

```
pip install numpy sentence-transformers
```

### Step 2: Load an embedding model

```py
from sentence_transformers import SentenceTransformer
import numpy as np
model = SentenceTransformer("all-MiniLM-L6-v2")
```

The `all-MiniLM-L6-v2` model generates 384-dimensional sentence embeddings.

Unlike a general-purpose chat model, an embedding model is designed to transform input into vector representations.

### Step 3: Encode a sentence

```py
sentence = "Machine learning is fun"
embedding = model.encode(sentence)
print(embedding)
print(embedding.shape)
```

The output contains numerical values, and its shape should be:

```
(384,)
```

This indicates that the returned embedding has 384 dimensions.

The actual numerical values are generated by the model and may be omitted from printed output for readability.

### Step 4: Encode multiple sentences

```py
sentences = [
    "There are 25 paid leave days.", 
    "There are 24 vacation days.", 
    "I love pizza."
]
embeddings = model.encode(sentences)
print(embeddings.shape)
```

Expected shape:

```
(3, 384)
```

There are three sentences, each represented by a 384-dimensional vector.

## Comparing sentences using cosine similarity

You can calculate cosine similarity with scikit-learn, which provides a convenient implementation.

Install it if necessary:

```
pip install scikit-learn
```

Then compare the sentences:

```py
from sentence_transformers import SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity
model = SentenceTransformer("all-MiniLM-L6-v2")
sentences = [    
    "There are 25 paid leave days.",    
    "There are 24 vacation days.",    
    "I love pizza."
]
embeddings = model.encode(sentences)
scores = cosine_similarity(embeddings)
print(scores)
```

This produces a similarity matrix comparing each sentence with every other sentence.

For three sentences, the result is a `3 X 3` matrix. The diagonal entries should be approximately `1`, because each vector is being compared with itself.

The other entries show how similar the model considers each pair of sentences.

### Compare two sentences directly

```py
sentence_a = "There is a traffic jam."
sentence_b = "Traffic is very heavy."
embedding_a = model.encode([sentence_a])
embedding_b = model.encode([sentence_b])
score = cosine_similarity(embedding_a, embedding_b)[0][0]
print(score)
```

The output is a numerical similarity score. Its precise value depends on the model, so don't assume a particular score without running the code.

### What happens next?

In an embedding-based retrieval system:

1. Generate embeddings for your knowledge-base documents.
2. Generate an embedding for the user's query.
3. Compare the query vector with document vectors.
4. Rank the documents by similarity.
5. Retrieve the most relevant documents or chunks.

This is the bridge between embeddings and the RAG pipeline from the previous lesson.

## How embeddings improve RAG

Recall the basic RAG pipeline:

User question → Retrieval → Relevant context → LLM → Answer

In the previous lesson, retrieval was implemented using simple keyword checks. This lesson shows how vector-based retrieval can make that stage more semantic.

### Keyword retrieval versus vector retrieval

| Feature             | Keyword-based retrieval                         | Embedding-based retrieval                                                    |
| ------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------- |
| Main approach       | Match words or terms                            | Compare numerical representations                                            |
| Different wording   | Can struggle                                    | Can identify semantic relationships                                          |
| Spelling errors     | Often problematic                               | May be more tolerant, depending on the error and model                       |
| Synonyms            | Need explicit handling in basic implementations | May be recognized through learned representations                            |
| Meaning             | Limited in simple exact-match systems           | Can capture semantic relationships                                           |
| Cost and complexity | Often simpler                                   | Requires embedding generation and vector comparison or search infrastructure |

Neither approach is universally best. Hybrid systems often combine lexical search and vector search.

### Example: A small knowledge base

Suppose the knowledge base contains:

1. “The employee receives 25 paid leave days.”
2. “The office is located in Delhi.”
3. “The company uses Python for backend development.”

The user asks:

> “How many vacation days does the employee get?”

A basic keyword search may struggle if it expects the phrase `"paid leave"`.

With embedding-based retrieval, the system can compare the question's embedding against the document embeddings. The first document may receive the highest similarity score because “vacation days” and “paid leave days” are semantically related.

The retrieved document can then be supplied to the LLM as context.

### The complete embedding-based RAG flow

1. Knowledge base: Documents are split into useful chunks
2. Embedding model: Convert each chunk into a vector
3. Vector database: Store vectors and associated text or metadata
4. User query: Convert the question into an embedding
5. Similarity search: Find the most relevant stored vectors
6. LLM: Use retrieved context to generate an answer

A vector database such as Qdrant can store and search embeddings efficiently. For a small dataset, you can also calculate similarities directly in Python without a dedicated vector database.

Embeddings improve the retrieval process, but they do not guarantee that the correct information will always be retrieved or that the LLM will always answer correctly.

## Important technical clarifications

### Real embeddings are not manually assigned feature scores

The instructor's sweetness-and-crunchiness example illustrates vectors, but actual language embeddings are usually learned by a model trained on large datasets. Their dimensions generally do not correspond to explicit properties such as sweetness or age.

### A computer is not limited to exact keyword matching

Traditional string search matches characters or terms according to its search rules. Computers can also perform semantic search when supplied with suitable models and algorithms. Embeddings are one way to enable this.

### A larger vector is not automatically more accurate

The lesson mentions models with different vector sizes. Dimension alone does not determine performance. The model's architecture, training data, task suitability, and retrieval setup all matter.

### Similarity scores are not universal measures of meaning

A score of `0.5` is not a universal threshold for “somewhat similar.” Compare scores in the context of the chosen model and evaluate retrieval performance on representative examples.

### Embeddings do not eliminate every spelling error

Embedding models can be robust to many wording variations, but performance on misspellings depends on the model, language, and error type. Vector search is not a guarantee of finding the right document.

### Embeddings and vector databases are different things

- Embedding model: Converts text or other supported data into vectors.
- Vector database: Stores vectors and supports similarity search, often with metadata filters.
- Cosine similarity: One possible measure for comparing vectors.
- RAG: Uses retrieval to supply relevant context to a generative model.

These components work together, but they are not interchangeable.

## Important questions

### Q1. What is an embedding?

An embedding is a numerical vector representation of data generated by a model. It enables systems to compare data points based on relationships learned by that model.

### Q2. Why are embeddings useful in RAG?

They allow the retrieval component to find semantically related information even when the user's wording differs from the wording in the knowledge base.

### Q3. What is a vector?

A vector is an ordered collection of numerical values. An embedding model represents each supported input as such a vector.

### Q4. What is an embedding dimension?

It is the number of numerical values in an embedding. For example, `all-MiniLM-L6-v2` produces 384-dimensional sentence embeddings.

### Q5. What is cosine similarity?

Cosine similarity compares the directions of two nonzero vectors using the cosine of the angle between them. It is commonly used to estimate semantic similarity between embeddings.

### Q6. Does a higher cosine similarity always mean two sentences have the same meaning?

No. It indicates that their vectors point in more similar directions. The relationship between a score and actual semantic relevance depends on the model and application.

### Q7. What is the difference between keyword search and semantic search?

Keyword search primarily looks for matching terms. Semantic search aims to retrieve information based on meaning or relationships, often using embeddings.

### Q8. What is the difference between an embedding model and an LLM?

An embedding model produces vector representations for tasks such as similarity search. An LLM generates or transforms text and may perform other language tasks. Some model families support both types of capabilities, but the tasks are different.

### Q9. What happens when an embedding-based RAG system receives a query?

The system embeds the query, searches for relevant stored vectors, retrieves associated content, and passes that content to the LLM as context.

### Q10. Why use a vector database?

A vector database provides infrastructure for storing, indexing, and searching vectors at scale, often with metadata filtering and other retrieval features.
